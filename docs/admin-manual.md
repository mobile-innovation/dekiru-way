# 管理画面 運用マニュアル

「できる道」の管理画面（`/admin`）を日常的に運用する人向けの手順書です。
実装の詳細は [`implementation-decisions.md`](implementation-decisions.md) §7-novies、
API 仕様は [`api.md`](api.md) を参照してください。ここでは「何をどう操作するか」だけをまとめます。

---

## 1. 前提知識（用語）

「できる道」では、利用者が残す情報を次の2つの単位で扱います。

| 用語 | 意味 |
| --- | --- |
| **道**（Road） | 一人の「困りごと」から始まる記録のまとまり。タイトル・できなくなったこと・やりたいこと・タグなど |
| **経験**（Attempt / 投稿） | 道の中で「試したこと」を1件公開したもの。管理画面では基本的に「経験」と呼ぶ |

1つの道には複数の経験がぶら下がります。**道自体の内容も、道の中の経験も、それぞれ別に公開チェックされます。**
道が確認待ち・公開停止のときは、その道に属する経験がどんな状態でも画面には出ません。

### 状態（モデレーション状態）

経験にも道にも、次の3状態があります。

| 状態 | 画面表示 | 意味 |
| --- | --- | --- |
| `pending` | **確認待ち** | まだ判断されていない。公開されない |
| `approved` | **公開中** | 利用者に公開されている |
| `rejected` | **公開停止** | 運営が公開しないと決めた。公開されない |

新しく登録・公開された道/経験は、まず AI が内容を確認します。

- AI が「問題なし」と判断 → 自動的に **公開中**（人の確認は不要）
- AI が「要確認」「判断できず」と判断、または AI が設定されていない → **確認待ち**になり、管理画面での判断待ちになる

つまり管理画面で運営が見るのは、基本的に「AI が判断に迷ったもの」だけです。

---

## 2. ログイン

- URL: `/admin/login`
- **一般利用者の Google ログインとは完全に別のアカウント**です（メールアドレス＋パスワード）
- ログインすると 8 時間はログインしたままになります（それ以降は自動的にログアウト）
- パスワードを 10 回連続で間違えると 1 分ほどロックされます（それ以上の試行はできません）

ログインできない・パスワードを忘れた場合は「7. 管理者アカウントの管理」を参照してください。

---

## 3. 画面の見方

ログインすると次のメニューが並びます。

| メニュー | URL | 何をする画面か |
| --- | --- | --- |
| ダッシュボード | `/admin` | 今すぐ確認すべきものが一目でわかる入口 |
| 経験を確認 | `/admin/moderation` | 確認待ちの**経験**を1件ずつ判断する |
| 道を確認 | `/admin/roads` | 確認待ちの**道**を1件ずつ判断する |
| 公開されている経験 | `/admin/posts` | 全経験の一覧（状態で絞り込み・検索・あとから公開停止も可） |
| 操作ログ | `/admin/audit` | 誰が・いつ・何を判断したかの記録 |

### ダッシュボード（`/admin`）

上から順に次の情報が並びます。

1. **確認が必要** — 「経験の確認」「道の確認」それぞれの件数。0件なら「今はありません」と出ます。件数をクリックするとそのまま確認画面へ移動します
2. **現在の状況** — 利用者数・道の数・公開されている経験の数・直近7日に公開・更新された数
3. **最近の動き** — 直近にできた道／公開・非公開になった経験の一覧（実際の記録のみ表示。作り物のデータは出ません）
4. **管理メニュー** — 各画面への入口。「利用者を見る」「通報・対応を見る」は**未実装のため準備中**と表示されるだけで、押しても何も起きません

**基本の運用は「まずダッシュボードを開き、確認が必要な件数があればそこから確認画面に入る」だけで足ります。**

---

## 4. 経験を確認する（`/admin/moderation`）

利用者が公開しようとした「試したこと」の確認待ちキューです。古いもの（待たせているもの）から順に並びます。

各カードには次が表示されます。

- 状態バッジ・AI の判定（問題なし／要確認／判断できず）
- **困ったこと → 試したこと → 結果** の順の内容（困ったことは道から引用）
- 気づき（あれば）
- AI が挙げた理由と、該当した場合のカテゴリタグ（下記参照）
- どの道に属する経験か（「道『○○』より」）

### AI のカテゴリ（「要確認」の理由）

| カテゴリ | 内容 |
| --- | --- |
| 個人情報 | 氏名・住所・電話番号・メール・勤務先・学校名・SNSアカウントなど、個人を特定できる情報 |
| 医療的断定 | 診断・治療方針の断定、「必ず治る」「絶対に効く」等、他人への医療指示 |
| 誹謗中傷 | 特定の個人・団体への攻撃 |
| 宣伝・スパム | 商品・サービスの宣伝、勧誘、外部サイトへの誘導 |
| 不適切表現 | 差別的・暴力的・わいせつな表現、その他公序良俗に反する内容 |
| その他 | 上記に当てはまらないが公開が不適切と AI が判断したもの |

**「うまくいかなかった」「変化がなかった」という後ろ向きな結果そのものは問題ではありません。** AI にもそう指示してあるので、通常はそれだけで確認待ちにはなりません。

### 判断のしかた

各カードの下に2つのボタンがあります。

- **公開する** — そのまま公開してよい場合
- **公開しない** — 内容に問題があり公開すべきでない場合（確認ダイアログが出ます）

判断に迷ったら、「内容を見る」で詳細画面（`/admin/posts/{id}`）を開くと、写真・すべての項目・過去の操作ログも確認できます。

---

## 5. 道を確認する（`/admin/roads`）

考え方は経験の確認と同じです。道の場合はタイトル・できなくなったこと・やりたいこと・困っている場面・進捗・次に試すこと・メモ・**タグ**が審査対象になります。

初期表示は「確認待ち」だけですが、上部のタブで「すべて／確認待ち／公開中／公開停止」を切り替えられます。

「内容を見る」で開く詳細画面では、その道に属する経験の一覧（公開状態つき）と、道自体の操作ログが確認できます。

---

## 6. 公開されている経験の一覧（`/admin/posts`）

いま「確認待ち」になっているもの以外も含めた、経験の全体一覧です。

- 上部タブで状態を絞り込み（すべて／確認待ち／公開中／公開停止）
- 本文・困りごと・目標のキーワード検索
- 各経験の詳細画面（`/admin/posts/{id}`）から次の操作ができます:
  - **公開を停止**（公開中 → 確認待ちに戻す。取り下げ）
  - **やっぱり公開する**（公開停止 → 公開中に戻す）
  - **AI でもう一度チェック** — 判定結果だけを更新する（状態は自動では変わらない。結果を見て人が判断する）

道の詳細画面（`/admin/roads/{id}`）にも同じ3操作があります。

> 運営メモ（判断の理由をメモとして残す欄）は API 上は存在しますが、**現在の画面には入力欄がありません**。表示だけはされるので、必要なら開発側に運用方法を相談してください。

---

## 7. 操作ログ（`/admin/audit`）

「誰が・いつ・何を・どの経験／道に対して行ったか」の記録です。新しい順に並びます。

| 操作名 | 意味 |
| --- | --- |
| ログイン | 管理者がログインした |
| 公開する | 確認待ち → 公開中 にした |
| 公開しない | 確認待ち → 公開停止 にした |
| 公開を停止 | 公開中 → 確認待ち に戻した |
| やっぱり公開する | 公開停止 → 公開中 にした |
| 確認待ちに戻す | 公開停止 → 確認待ち に戻した |
| AI でもう一度チェック | AI 判定だけを再実行した |

各行の「対象の経験 →」「対象の道 →」から、その経験／道の詳細画面に直接飛べます。
ログは消せません（誰が何をしたかの証跡として残り続けます）。

## 8. 管理者アカウントの管理

管理者アカウントは、利用者の Google アカウントとは別に、メール＋パスワードで管理します。

### 新しい管理者を追加する／パスワードを変更する

サーバー上で次のコマンドを実行します（開発者に依頼してください）。

```bash
npm run admin:create -- 担当者のメールアドレス "パスワード" "表示名"
```

- すでに同じメールアドレスの管理者がいる場合は、パスワードと表示名が上書きされます（＝パスワード再設定として使えます）
- パスワードは 8 文字以上にしてください
- 開発環境では `npm run db:seed` を実行すると `admin@example.com` / `dekiru-admin` が自動的に用意されます（**本番では使わないでください**）

### 管理者を無効化したいとき

現時点の管理画面 UI からは管理者の無効化・削除はできません。必要な場合は開発側に直接データベースでの対応を依頼してください（今後の改善候補です）。

## 9. よくあるトラブル

| 症状 | 原因・対処 |
| --- | --- |
| ログインできない | メールアドレス／パスワードを確認。10回連続で間違えると一時ロックされるので、1分待って再試行 |
| `/admin` を開くと毎回ログイン画面に戻される | セッションが切れている（8時間経過）か、サーバー側の設定（`AUTH_SECRET`）が変わった可能性。開発側に確認を依頼 |
| 公開したはずの経験がなかなか公開されない | 「確認待ち」になっている可能性が高い。`/admin/moderation` を確認 |
| 公開したのに検索に出てこないと利用者から連絡がある | 経験自体は公開中でも、**その経験が属する道が確認待ち／公開停止**だと表示されません。`/admin/roads` で道の状態も確認する |
| すべての新規公開が「確認待ち」になってしまう | AI 審査用の API キー（`ANTHROPIC_API_KEY`）が設定されていない可能性。この場合は判定できないため安全側で全件「確認待ち」になる仕様。開発側に確認を依頼 |
| AI の判定に納得できない／もう一度見てほしい | 詳細画面の「AI でもう一度チェック」で再判定できる。ただし状態は自動で変わらないので、結果を見た上で改めて「公開する／公開しない」を選ぶ |

---

## 10. 日常運用の流れ（おすすめ）

1. `/admin` を開く
2. 「確認が必要」に件数があれば、それぞれの確認画面へ
3. **経験を確認**: 内容（困ったこと→試したこと→結果）と AI の理由を読み、公開する／公開しないを判断
4. **道を確認**: タイトル・内容・タグを読み、公開する／公開しないを判断
5. 迷うものは「内容を見る」で詳細画面を開いてから判断する
6. 定期的に `/admin/posts` で状態全体を見渡し、必要なら公開停止・再公開を行う
7. 対応内容や不明点があれば `/admin/audit` で経緯を振り返る
